
# decision-engine 要求仕様書

## ＜メッセージ関与度・意図判定＞

### ユーザープロファイル, 意図分類: 上位要求 R01

**要求**: ユーザープロファイル定義に基づき、メンションの有無にかかわらず受信メッセージの関与度とアクション種別を自動判定できるようにしたい。
**理由**: グループチャットやチャネルでメンションがない相談・障害報告を見落とさず、かつ無関係な雑談や自分自身の送信メッセージを除外して業務効率を高めるため。
**説明**: `config/user_profile.yaml` に定義された氏名・役職・担当領域・キーワード・除外条件と、ローカルLM Studio（OpenAI互換API）を用いる。

###### ＜関与度・アクション種別判定仕様＞

- ■■■ **S01-01**: `user_profile.yaml` の担当領域・キーワード・役割を参照し、メンションがないメッセージであっても担当領域に該当する場合は `is_relevant: true` と判定し、意図に応じて `action_type` を `consultation`, `task`, `info` のいずれかに分類する。
- ■■■ **S01-02**: 送信者がユーザー自身（プロファイルの氏名またはメールアドレスに一致）であるメッセージ、または担当業務・キーワードと無関係な雑談メッセージを受信した場合は `is_relevant: false` かつ `action_type: "ignore"` と判定する。

## ＜アクション別データ抽出・生成＞

### 相談解析, 返信質問案生成: 上位要求 R02

  **要求**: 相談（`consultation`）と判定されたメッセージに対して、回答に必要な不足情報を抽出し、そのまま返信可能なヒアリングメッセージ案を生成できるようにしたい。
  **理由**: 情報不足のトラブル相談等に対して、確認事項の整理と返信文作成にかかる時間を短縮するため。
  **説明**: 抽出された不足情報は `consultation.missing_points`、返信案は `consultation.suggested_reply` として構造化する。

###### ＜不足情報抽出・返信案生成仕様＞

- ■■■ **S02-01**: `action_type` が `consultation` と判定された場合、回答・調査に必要な不足情報（前提条件、発生環境、エラー内容、希望期限など）を `consultation.missing_points` 配列として抽出する。
- ■■■ **S02-02**: 抽出した不足情報を踏まえ、相手へそのままTeamsで返信可能な丁寧な日本語のヒアリングメッセージ案を `consultation.suggested_reply` に生成する。

### タスク抽出, 構造化: 上位要求 R03

**要求**: 作業依頼（`task`）と判定されたメッセージから、ToDo管理に必要なタスク属性を構造化して抽出できるようにしたい。
**理由**: チャット上の依頼事項を手作業で転記することなくローカルDBへタスク登録できるようにするため。
**説明**: タスク属性として件名（`title`）、詳細説明（`description`）、期限（`due_date`）、優先度（`priority`）を抽出する。

###### ＜タスク属性抽出仕様＞

- ■■■ **S03-01**: `action_type` が `task` と判定された場合、メッセージ本文からタスクの件名（`task.title`）、詳細説明（`task.description`）、期限（`task.due_date`、指定がない場合は `null`）、および優先度（`task.priority`: `high` / `normal` / `low`）を構造化して抽出する。

## ＜LLM出力検証・耐障害性＞

### JSONパース, リトライ制御: 上位要求 R04

**要求**: ローカルLLMのレスポンスから確実にJSONを抽出・検証し、フォーマット不正時にはリトライと安全なエラーハンドリングを行えるようにしたい。
**理由**: 推論モデル（DeepSeek-R1やQwen等）が出力する `<think>` タグやMarkdownコードブロック、一時的なJSON構文崩れによってシステムがクラッシュするのを防ぐため。
**説明**: 出力文字列のクレンジング処理とPydanticスキーマ検証、および最大リトライ回数に基づく再試行を行う。

###### ＜レスポンス整形・リトライ仕様＞

- ■■■ **S04-01**: LM Studioからの応答文字列に `<think>...</think>` タグや `json ... ` コードブロックが含まれる場合、それらを除去してJSONオブジェクト部分を抽出し、スキーマ検証を行う。
- ■■■ **S04-02**: JSON抽出またはスキーマ検証に失敗した場合、設定された最大リトライ回数までLM Studio APIへ再要求を行い、最終的に失敗した場合は例外を送出して呼び出し元で `failed/` 退避等の安全なエラー処理を行わせる。
